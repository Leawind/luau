# Luau Runtime Mod 设计文档

## 定位

Luau Runtime Mod 是供其他 Minecraft 模组使用的 Luau 运行时基础库模组，模组 ID 为 `luau`。

本项目首先服务于 SuterXOM，但公开 API 不包含设备、网络、物品或 Minecraft 世界等 SuterXOM 专有概念。它的定位类似于 KubeJS 使用的 Rhino：上层模组依赖稳定的 Java API，本项目负责语言实现、运行隔离、资源限制和调试能力。

本项目负责：

- Luau 源码的解析、类型检查、编译和执行。
- 相互隔离的脚本实例及其生命周期。
- 由宿主模组实现的虚拟模块。
- Java 与 Luau 安全值之间的编解码。
- 沙箱、资源限制、执行中断和调试能力。
- Luau 原生库的跨平台构建、内嵌和装载。

本项目不负责：

- Minecraft 服务端 tick 调度和世界级预算分配。
- 设备事件队列、端口、设备网络和世界交互。
- 脚本源码、编译诊断或设备状态的持久化。
- 验证和提交脚本产生的游戏命令。
- 调试 GUI、调试网络协议和玩家权限。
- 文件系统、网络、进程或任意 Java 类的脚本绑定。
- SuterXOM 的物品令牌和账本。

## 设计原则

### 默认不信任脚本

玩家提供的源码、参数和持久化数据都视为不可信输入。脚本只能使用 Luau 安全标准库和宿主显式授予的虚拟模块，不得获得 Java 对象、Minecraft 对象、文件路径、网络连接或其他隐式宿主能力。

### 宿主显式授予能力

宿主模块按名称显式注册。编译器和运行时只能解析本次程序声明的源码模块与宿主模块，未知模块、真实文件路径和动态外部模块加载均被拒绝。

### Java API 稳定，原生实现可替换

Luau 的 C++ 分析接口可能随上游演进。上游接口封装在本项目内部，不泄漏到公开 Java API；公开 API 通过 `io.github.suterxom.luau.v1.api` 这类版本化包维护兼容性。

### 失败应可分类和恢复

语法错误、类型错误、运行时错误、宿主错误、资源超限、主动终止和原生库装载失败具有不同的结构化结果。普通脚本错误不表现为日志或无类型的 Java 异常。

### 调试不得阻塞服务器

命中断点时，当前 Luau coroutine 进入可恢复的暂停状态，执行调用立即返回 Java。暂停状态可以跨 Minecraft tick 保存，不占用服务器线程，也不影响其他脚本实例。

## 技术方案

### Luau 实现

项目直接使用官方 `luau-lang/luau` C++ 实现，并固定到明确的上游 commit。固定版本和 commit 记录在构建信息和最终 JAR 的清单中，以便复现构建和排查兼容性问题。

本项目只使用 Luau 字节码解释器，不启用原生代码生成或 JIT，以减少可执行内存、安全审计和平台差异方面的复杂度。引入原生代码生成属于单独的设计变更，不通过默认执行模式悄然改变。

Java 与 C++ 之间使用 JNI。JNI 层只提供 Java 实现所需的窄接口，不将 Luau 指针、栈索引或原始 C++ 对象暴露为公开 Java API。

### Minecraft 加载器兼容

运行时实现不引用 Minecraft 类或加载器 API。最终 JAR 同时包含 `fabric.mod.json`、`META-INF/mods.toml` 和 `META-INF/neoforge.mods.toml`，三种加载器共用同一个构建产物。模组没有加载器专用入口点，公开 API 第一次被调用时才初始化原生运行时。

由于没有 Minecraft 源码兼容层，本项目不使用 Stonecutter，也不为每个 Minecraft 版本分别复制源码或生成 JAR。

基线为 Java 17 和 Minecraft 1.20.1 及以上。提高 Java 或 Minecraft 最低版本属于兼容性变更，必须在发布说明中记录。

### 包结构

所有 Java 源码和类型位于 `io.github.suterxom.luau` 根包下：

```text
io.github.suterxom.luau
├── v1.api: compile、debug、host、runtime、value
└── internal: jni、loader、validation
```

`v1.api` 是稳定的公开 API，`internal` 中的类型不属于兼容性承诺，公开 API 不引用 `internal` 类型。

## 编译

### 程序模型

一次编译请求由唯一的根模块名、一个或多个以内存字符串提供的 Luau 源码模块、本次允许使用的宿主虚拟模块及其类型声明组成。

模块名是逻辑标识符而非文件路径，运行时不根据模块名访问文件系统。宿主可以自行从任何存储后端读取源码，交给本项目时必须是完整的内存数据。模块名、模块数量和总源码大小在编译前校验，违反契约以 `IllegalArgumentException` 拒绝。

编译先把宿主模块的类型声明加入分析环境，在 strict 模式下对根模块和全部源码模块做类型检查，仅在没有诊断时把每个模块编译为 bytecode，最后返回诊断和不可变的已编译程序。

类型检查和编译不依赖共享的可变 VM 状态，可以在服务器工作线程执行，不要求 Minecraft 服务器线程。

### 诊断

`CompilationResult` 返回零个或多个不可变的 `CompilationDiagnostic`。诊断包含阶段、严重度、稳定的本项目错误代码、模块名、结构化源码范围和面向用户的上游原始消息。

源码范围用 `SourceRange` 表示起止行列，行列都从 1 开始，`0` 表示未知，`SourceRange.UNKNOWN` 是约定的未知值，结束位置沿用 Luau 约定指向范围末尾之后。parse 和 type 诊断的位置来自 Luau 的 `Location`；compile 阶段的失败没有位置，使用 `SourceRange.UNKNOWN`。

消息文本只保留 Luau 的原始诊断，不拼接行列前缀。调用者从结构化字段取得源码范围，不解析消息文本；稳定控制流只能依赖阶段、严重度和错误代码，Luau 上游诊断字符串可以变化。

阶段分为 parse、type、lint 和 compile，诊断代码按阶段固定为少数几种。当前只产生 parse、type 和 compile 阶段的 error：lint 检查未启用，`Stage.LINT` 与 `Severity.WARNING`、`Severity.INFORMATION` 尚无产出，属于预留取值。

语法错误和类型错误通过 `CompilationResult` 返回，不抛 Java 异常。参数违反 Java API 契约、在关闭后使用句柄或原生环境损坏等宿主错误才使用 Java 异常。

### 已编译程序

`CompiledChunk` 是不可变的 `AutoCloseable` 对象，保存各模块的 bytecode、模块依赖、源码标识和编译时使用的宿主模块接口版本。

公开 API 不返回可修改的原始 bytecode。运行时只执行由当前兼容编译器生成、并经内部装载校验的 bytecode。

`CompiledChunk` 既可以在一次性 VM 中直接执行，也可以通过 `createInstance()` 创建持久实例；两条路径在同一个 `CompiledChunk` 上串行化。关闭 chunk 会清零其 bytecode，之后的执行和创建实例都会失败。

第一版不支持把已编译程序跨服务器重启持久化。上层模组应保存源码，需要时重新编译。

## 宿主虚拟模块

### 模块定义

`HostModule` 同时定义完整且带版本的模块名、用于类型检查的 Luau 声明、运行时导出的 factory 和接口版本标识。

类型声明是只参与类型检查的 strict Luau 模块体，不编译也不执行：

```luau
return (nil :: any) :: {
    send: (string) -> boolean,
    receive: () -> buffer?,
}
```

类型声明与运行时导出必须由宿主共同维护。运行时验证导出名称等基本约束，声明是否准确最终由注册模块的宿主负责。编译过程不调用 factory；每个脚本实例、每次一次性执行各自从 factory 取得一份独立的导出表。

每个脚本实例只获得创建它时明确传入的模块集合。注册表中存在某个模块，不代表所有脚本都自动获得该模块。

### require

沙箱提供本项目实现的 `require`：

- 参数必须是字符串模块名。
- 只允许请求当前程序已登记的源码模块或宿主模块。
- 每个脚本实例缓存模块执行结果，源码模块必须返回恰好一个值。
- 循环依赖返回明确的模块错误。
- 不支持相对路径、环境变量、搜索路径或原生动态库加载。

宿主模块的导出表在构造完成后设为只读，脚本不能替换宿主函数或修改共享标准库。

### 宿主函数

宿主函数只接收当前调用的受控 `HostCallContext` 和已解码的安全参数列表，只返回安全值，或抛出可转换为 Luau 运行时错误的 `HostCallException`。Java 异常不穿过 JNI 边界：未预期的 Java 异常在 JNI 层捕获并转换为宿主内部错误，同时保留供服务端日志使用的原因。

`HostCallContext` 承载宿主自己的 Java 能力：能力按显式类型键放入上下文，宿主函数通过 `find` 或 `require` 读取，这些对象永远不会编码或暴露给 Luau。上下文同时累计 `recordOutputBytes` 登记的宿主输出成本。一个上下文对应一个上层逻辑调用，不应并发共享。

宿主函数必须快速、确定且不阻塞。文件访问、数据库操作或其他可能长时间阻塞的工作由上层模组在脚本执行之外调度。

## 安全值

Java 与 Luau 之间只支持以下值：

- `nil`
- `boolean`
- 双精度 `number`
- UTF-8 字符串
- 字节 buffer
- 数组
- 仅以字符串为键的表

公开 Java 表示使用不可变的 sealed `LuauValue` 层次。数组、表和 buffer 在构造时防御性复制，公开访问时不泄漏可修改的内部存储。

以下值不得跨越 Java/Luau 边界：

- Luau 函数。
- coroutine 或 thread。
- userdata 和 light userdata。
- metatable。
- 任意 Java 对象或类。
- 包含循环引用的数组或表。
- 使用非字符串键的表。

每次编解码都受最大深度、节点数、字符串字节数、buffer 字节数和总字节数限制。超出限制产生结构化的编码结果或参数异常，不允许递归到 JVM 或原生栈溢出。

SuterXOM 的 16 字节物品令牌可用 buffer 表示，但固定长度、不可变性、权限和账本语义由 SuterXOM API 验证，不属于本项目通用值层。

## 脚本实例

### 隔离方式

每个 `ScriptInstance` 拥有独立的 `lua_State`、allocator、全局环境和模块缓存，不同实例不共享可变 Luau 对象。

不使用同一个 VM 中的内存分类来模拟隔离，原因是：

- 独立 allocator 才能可靠执行每实例硬内存上限。
- 关闭或重置一个实例不会影响其他实例。
- 暂停的调试会话不会占用其他实例的执行状态。
- 一个脚本无法通过共享 registry 或对象引用污染其他脚本。

标准库代码可以来自同一个原生二进制，但每个 VM 的可变运行状态相互独立。

### 初始化与导出

创建实例后，运行时在受预算控制的初始化调用中执行根模块。根模块返回一个只供宿主调用的导出表。上层模组按名称调用导出的 Luau 函数，例如 SuterXOM 将设备事件名映射为处理函数名。

一个实例同一时刻只允许一个初始化或导出调用。调用尚未结束或处于调试暂停状态时，再次调用其他导出立即失败；事件排队由上层模组负责。

实例及其调试器只能在实例的所有者线程使用；编译产物没有所有者线程，其方法由对象自身串行化。

### 执行结果

`ExecutionResult` 使用封闭的结构化类型：

- `Completed`：正常完成及返回值。
- `Paused`：命中断点、单步或主动暂停。
- `RuntimeFailed`：Luau 运行时错误、宿主边界错误或编解码错误。
- `LimitExceeded`：运行时间、中断检查、内存、宿主调用、宿主输出或编解码预算超限。
- `Terminated`：由宿主或调试器主动终止。

每个结果携带本次执行的指标：实际运行时间、interrupt/safepoint 检查次数、当前和峰值 VM 内存、宿主函数调用次数和宿主输出字节数。

运行时错误、资源超限和主动终止都会终止当前 coroutine。为避免继续使用已经部分修改的 Lua 全局状态，实例随后进入 faulted 状态，宿主必须调用 `reset` 或重新创建实例才能处理下一个事件。`reset` 使用原有 `CompiledChunk` 建立全新的 VM，并重新应用断点。

## 沙箱

创建 VM 时必须：

- 只打开 Luau 的安全标准库。
- 对标准库和共享 metatable 使用 `luaL_sandbox`。
- 对脚本线程使用 `luaL_sandboxthread`。
- 将所有自定义宿主表设为只读。
- 安装中断、调试、内存和线程生命周期回调。
- 不把指针信息暴露给脚本。

本项目不集成 Lute。Lute 面向通用程序的文件系统、HTTP、socket 和进程能力与“默认不信任脚本”的边界不一致。

即使 Luau 标准库本身是安全的，宿主模块仍可能破坏沙箱。所有宿主函数都必须遵守：

- 不返回 userdata 或 Java 对象句柄。
- 不提供反射、类加载或任意方法调用。
- 在访问上层状态前执行上层权限验证。
- 不在单次调用中执行无界循环或阻塞 I/O。
- 把可产生世界影响的操作写入上层命令缓冲，而不是直接修改世界。

## 资源限制

### 实例级限制

`InstanceConfig` 目前只配置 VM 的最大堆内存，配置值有允许区间，越界以参数异常拒绝。每个 VM 使用自定义 allocator 追踪当前和峰值分配；新分配会使实例超过硬上限时，allocator 拒绝分配，运行时将其转换为内存超限结果。内存统计不依赖 Java 堆或定期采样。

模块数量、单个宿主模块的导出数量、单模块源码与总源码大小、模块名和导出名长度、安全值编解码上限都以固定上限实现，超出时以参数异常或结构化结果拒绝。这些上限属于安全边界，不随脚本输入扩大。

### 调用级限制

`ExecutionBudget` 包含：

- 最大实际运行时间。
- 最大 interrupt/safepoint 检查次数。
- 最大宿主函数调用次数。
- 最大宿主输出字节数。

Luau 的 interrupt 回调保证在循环回边、调用、返回和 GC 等 safepoint 最终被调用，但不提供跨版本稳定的精确字节码指令计数。因此公开 API 使用“中断检查预算”，不承诺精确的 Luau 指令数。

运行时间只累计 VM 实际运行的时间，调试暂停期间不计时。同一事件在多次暂停和恢复之间累计使用同一个总预算，不能通过反复继续执行重置预算。

宿主函数自身的耗时包含在运行时间内。中断 safepoint 无法介入可能长时间运行的单次原生宿主函数，因此宿主函数不得阻塞。

世界级预算、设备优先级和每 tick 可执行多少实例由上层调度器负责，本项目只执行传入的单实例调用预算。

## 调试

### 调试能力

`ScriptDebugger` 提供：

- 设置、删除和清空源码断点。
- 请求在下一个可中断位置暂停。
- 继续执行。
- 单步进入、单步跳过、单步跳出。
- 终止当前调用。
- 查看暂停原因、当前源码位置和 Luau 调用栈。

第一版不提供任意局部变量、upvalue 或对象图遍历。这些能力可能泄漏宿主实现细节，并显著扩大安全和值编解码边界。

断点、暂停、恢复、终止和跨 coroutine 调用栈快照覆盖所有 Luau coroutine，并保留原宿主上下文与累计预算；依赖模块顶层加载中的断点通过可继续的 `require` 边界传播。

### 断点与单步

设置断点时，请求行被解析为该函数中可执行的实际行，Java API 返回解析后的位置，使客户端能够显示断点是否有效以及实际命中的行。

命中断点后，运行时记录暂停原因和当前源码位置，把 coroutine 置为暂停状态，并从当前 JNI 执行调用返回 `Paused`，同时保留 VM、coroutine、预算累计值和宿主上下文。暂停时当前事件仍未结束：SuterXOM 的命令缓冲继续由 SuterXOM 持有且不得提交，继续并正常完成后才可提交，终止、错误或超限时由 SuterXOM 丢弃。

单步按逻辑 Luau 调用栈深度定义：

- step-in 在下一处不同的可显示源码位置暂停。
- step-over 记录初始栈深和源码位置，在同层新位置或返回到更浅层时暂停。
- step-out 在调用栈低于初始深度后暂停。

单步只在单步期间启用逐指令回调，避免正常执行长期承担调试开销。原生/C 宿主函数内部不可单步，单步会在其返回 Luau 后继续。

### 并发控制

脚本实例具有所有者线程。创建、调用、检查暂停状态、恢复、单步、重置和关闭都必须在所有者线程执行，违反时抛出 `IllegalStateException`。

`requestPause` 和 `requestTerminate` 可以从其他线程调用，但只设置原子请求标志；真正的 VM 操作在所有者线程的 interrupt 回调中发生。调试网络处理线程不得直接读取或修改 Luau 栈。

## 原生库内嵌与装载

### 支持平台

第一版内嵌：

- Windows x86-64。
- Linux glibc x86-64。
- Linux glibc AArch64。
- macOS x86-64。
- macOS ARM64。

暂不支持 musl Linux、Windows ARM64、Android 和其他平台。支持矩阵属于发布产物契约；新增平台不改变 Java API。

### JAR 布局

所有支持平台的原生文件直接放入最终 JAR：

```text
META-INF/luau/natives/
├── linux-aarch64/libluau_jni.so
├── linux-x86_64/libluau_jni.so
├── macos-aarch64/libluau_jni.dylib
├── macos-x86_64/libluau_jni.dylib
└── windows-x86_64/luau_jni.dll
```

JAR 还包含记录文件路径、大小、SHA-256、目标平台、JNI ABI 版本和 Luau commit 的原生清单。运行时绝不从互联网或 Maven 下载原生库、辅助程序或其他平台文件；缺少对应平台文件时返回包含检测到的 OS、架构和当前支持列表的 `UnsupportedPlatformException`。

### 装载

JVM 不能直接从 JAR 内部装载动态库，因此装载器把当前平台的内嵌文件提取到临时目录。提取只复制 JAR 中已有的文件，不进行网络访问。

装载流程为：把 `os.name` 和 `os.arch` 规范化为平台 ID，按内嵌清单选择唯一匹配的原生文件，校验大小和 SHA-256，在文件锁下原子写入缓存目录并对磁盘文件再次校验，最后调用 `System.load` 并与 native 实现握手 JNI ABI 版本。

清单缺失、校验失败、文件被替换或 ABI 不匹配时禁止继续执行。装载器在同一 ClassLoader 中只初始化一次，之后的调用直接复用已装载的库。

## 生命周期与资源释放

`CompiledChunk` 和 `ScriptInstance` 实现 `AutoCloseable`。`close` 幂等，关闭后调用操作方法抛出明确的 `IllegalStateException`；关闭实例会释放其原生 VM、回调使用的全局引用和 bytecode。

实例只能在其所有者线程关闭，运行时不以 GC 或后台线程作为漏关闭的兜底手段。Minecraft 服务器停止时，上层模组负责关闭所有实例。

JNI 层集中管理原生句柄与异常：

- C++ 异常统一捕获并转换为 Java 内部异常。
- Java 异常统一捕获并转换为 Luau 宿主错误。
- 不允许 C++ 异常或 Luau long jump 越过 JNI 边界。

原生句柄是不透明的 `jlong`，不携带类型或代际信息，因此关闭后的句柄不能被再次使用：Java 侧在调用原生方法前检查状态，并在关闭与跨线程请求之间使用读写锁。带类型和代际信息的句柄属于尚未实现的目标。

## 版本与兼容性

本项目同时维护三种版本：

- 模组版本：面向发布和依赖声明。
- Java API 版本：体现在 `v1.api` 包路径中。
- JNI ABI 版本：Java 实现与内嵌原生库启动时握手。

Luau 上游 commit 不是公开 Java API 版本，但必须可以查询。更新 Luau 时必须运行完整的编译、沙箱、资源限制和调试回归测试。

`v1.api` 中已经发布的类型和语义遵循向后兼容原则：破坏性 Java API 变更使用新的版本包，仅内部 JNI 和 C++ 重构不改变 Java API 版本。该原则从第一个稳定版开始生效；发布流程把 0.x 和带预发布后缀的版本判定为 beta，beta 之间允许破坏性调整。

本项目不发布 Maven 构件。消费者把发布出来的通用 JAR 作为模组依赖引入，并在自己的加载器元数据中声明对模组 `luau` 的依赖。是否发布 Maven 及其坐标另行决定。

## 构建与发布

项目使用 Gradle 构建 Java 和最终 JAR，使用 CMake 构建 C++。普通构建只构建和测试当前平台的 native；生成可发布 JAR 的任务要求五个目标平台文件全部存在，缺少任何一个即失败，避免误发布只包含构建机平台的 JAR。

发布产物包含通用模组 JAR（`luau-<version>-universal.jar`）、sources JAR、第三方许可证、原生文件和校验和清单，以及构建版本、Luau 版本和 Luau commit 信息。即使不发布 Maven，也保留 sources JAR，便于 IDE 查看 API 源码和通过 Release 分发。

CI 分为普通构建和 tag 发布。普通构建在推送到 `main` 和针对 `main` 的 pull request 时运行，在五个平台上分别构建并运行测试，再汇总校验通用 JAR 包含全部目标平台文件。发布只由维护者推送 `v*` tag 触发：校验 tag 与项目版本一致，从同一 tag commit 构建全部平台原生文件，校验通用 JAR 后发布到 GitHub Releases（附 sources JAR）、Modrinth 和 CurseForge。`0.x` 版本和带预发布后缀的版本标记为 beta，其余标记为正式 release；发布凭据缺失时工作流失败，避免各平台发布状态不一致。

## 测试

回归测试必须覆盖以下边界：

- 正确源码可以通过 strict 类型检查并生成可执行程序，语法和类型错误带有正确的模块、诊断代码与源码范围。
- 未登记模块、循环依赖和非法模块名被拒绝。
- 安全值可以 Java → Luau → Java 往返，编解码上限在边界处生效。
- 宿主正常错误和未预期 Java 异常都不会穿过 JNI。
- 脚本不能访问文件、网络、进程、Java 类和外部模块，一个实例看不到另一个实例的可变状态。
- 无限循环和大量分配被硬限制终止且不影响其他 VM，深递归和恶意嵌套值不会造成栈崩溃。
- 错误、超限和终止后实例进入 faulted 状态，`reset` 后得到没有旧可变状态的新 VM。
- 断点解析到正确的模块和可执行行，暂停后 Java 调用返回且服务器线程被释放，暂停可跨 tick 继续并保持累计预算。
- 五个目标平台都能完成装载、版本握手、编译和执行；不支持的平台得到明确异常且不尝试联网；散列不一致时拒绝装载。
- 同一个 JAR 可被 Fabric、Forge 和 NeoForge 识别，专用服务器环境不加载客户端类。

## 第一版验收条件

第一版可以认为具备接入 SuterXOM 的条件，当且仅当：

- Fabric、Forge、NeoForge 使用同一个包含全部目标 native 的 JAR。
- 两个脚本实例之间不存在可观察的可变状态共享。
- 无限循环和内存爆炸都能被硬限制终止而不影响服务器进程。
- 宿主可以调用根模块导出函数并获得结构化结果。
- 断点暂停立即返回 Java，之后可以跨 tick 继续、单步或终止。
- 所有失败路径都能确定当前事件不可提交，并使实例进入明确状态。
- CI 能从 tag 对应的同一 commit 构建并发布可验证的 Release 产物。
